An AI operator that does the back-office job, then proves it.

You give it one sentence. It reads the mail and the PDF, follows company policy, works a real browser, asks a person before anything risky, and only says "done" after it has re-read the ERP to check.

The request in this demo

“Find the latest invoice from Acme Supplies Pvt Ltd, extract the amount and due date, enter it into our ERP, and tell me once it is done.”

What happens, in plain terms

You

Ask in one sentence

Type it, or say it with opsagent voice. You see the transcript and confirm before it runs.

The agent

Works it out

It looks up company policy for the steps you left out, then operates the mail portal and the ERP in a real browser.

You again

Approves the risky part

Before saving a bill it shows the exact values and every policy check. Code decides whether you are needed, not the model.

A verifier

Checks the result

A separate check, with no AI in it, re-reads the ERP and compares to the PDF. Only then does the agent report done.

What it actually saw and did

Real screenshots from one run, in order. Click any image to enlarge.

1 · Find the right invoice

The mail portal

Several look-alikes arrive: a reminder, and another vendor called "Acme Supply Co". The agent picks the latest invoice from Acme Supplies Pvt Ltd, following company policy AP-05.

2 · Open the message

The email and its attachment

The email states an amount, but the PDF is the authoritative source (policy AP-01). If the two disagreed, the agent would have to stop and ask a person.

3 · Read the PDF

The source document

It downloads and reads the PDF: invoice number, dates and the tax-inclusive total of INR 48,250.00. These are the values it is allowed to type.

4 · Fill the ERP form

Typing in the values

It signs in with credentials from a vault. The model only ever sees a placeholder, never the password. Labels are matched by name, so renamed buttons do not break it.

5 · Ask before saving

The approval prompt

Saving creates a payable, so it stops. The prompt lists the exact values and every policy check. INR 48,250 is over the INR 25,000 auto-approve limit, so a person must say yes.

Terminal text from the first end-to-end run, rendered as an image.
6 · Saved

The bill exists

The ERP shows the new bill next to the existing ones. But the agent does not trust its own click: it still has to prove it.

7 · Proof

Verified, then reported

The verifier re-reads the ERP through its API and compares values to the PDF. The report names what was entered, where it came from and the evidence.

Approval is tied to what you saw

The approval carries a digest of the tool, its arguments and the form values. It is checked again at the instant of execution, so it cannot be reused on a different page state.

Done has to be proven

Any value the agent typed must also appear in a source document it read. A made-up amount cannot confirm itself just because the ERP now contains it.

Under the hood

The model only proposes one action per step. Everything with consequences goes through one tool registry that checks permissions, input shape and risk, retries only when it is safe, and writes a redacted audit log.

Run it yourself

git clone https://github.com/Harshaaalll/opsagent && cd opsagent
python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
playwright install chromium-headless-shell
cp .env.example .env        # add your GEMINI_API_KEY to .env

python -m opsagent run --visible "Find the latest invoice from Acme Supplies Pvt Ltd, extract the amount and due date, enter it into our ERP, and tell me once it is done."
python -m opsagent voice    # speak the request instead
pytest                      # 31 tests, no API key needed
python -m evals.run         # the 12 scenarios against the real agent

There is no public live agent. A public endpoint would let anyone spend the API key and drive a browser that can write records, so the agent runs locally against the bundled mock company.

Limits, stated plainly

  • Validated on two mock web apps and one workflow family. Generalisation is shown, not proven.
  • It reads pages as text. No vision, no desktop applications.
  • A crash loses the run: there is no durable queue yet. Approvals happen at the terminal.
  • Voice is input only. It transcribes, shows you the text, and runs after you confirm.
